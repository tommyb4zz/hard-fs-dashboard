# MB1381 board-design evidence and remaining hardware information

This is a read-only comparison of the supplied CAD package with the firmware. No firmware, board, adapter or physical CAN bus was operated. CAD files describe an intended design; they do not establish which revision, parts, jumpers or modifications are present on the user's board.

## Sources and reproducibility

- Supplied package: `/Users/youseffarahat/Downloads/mb1381-bdp/readme.txt`, version 5.0, dated 10 October 2024. It records changes to the LCD and eMMC reference in revision B.
- Altium project: `/Users/youseffarahat/Downloads/mb1381-bdp/MB1381B/Altium_Designer/MB1381.PrjPcb`. Lines 544–546 define H745XI; 1247–1249 define H750XB; 1286 selects `STM32H750XBH6U` for U6. Lines 1353/1416/1479 select SB6/SB17/SB45 ON; lines 1542/1605/1746/1809 select SB5/SB18/SB44/SB46 OFF for H750XB. These support the repository's LDO configuration; actual bridge population is unverified.
- Project parameters at lines 1874–1892 specify assembly revision **04**, PCB revision **B**, board reference **MB1381** and document date **27 September 2024**. These identify the design package as B04; they do not establish the revision of the physical board.
- Binary `.SchDoc` files were read as OLE compound documents with `olefile` 0.47 installed only in ignored `build/bdp-review/parser-deps`. Their `FileHeader` stream contains little-endian length-prefixed records. The extraction takes the low 24 bits as record length, removes the terminal NUL and decodes text as Windows-1252. Extracted JSON and numbered text are under `build/bdp-review/raw/`. Record numbers below are **zero-based stream record ordinals**, not CAD sheet pin numbers or text-file line numbers.
- [ST UM2488 Rev 10](https://www.st.com/resource/en/user_manual/um2488-discovery-kits-with-stm32h745xi-and-stm32h750xb-mcus-stmicroelectronics.pdf), sections 6.4, 6.9, 6.12–6.15, Table 17 and Table 19, corroborates board power, memory, I/O assignments and replacement history.
- [Microchip MCP2561/2FD datasheet](https://ww1.microchip.com/downloads/en/DeviceDoc/20005284A.pdf), sections 1.1 and 1.7.1–1.7.9, establishes transceiver digital-I/O supply, CANH/CANL and standby behavior.
- [ISSI IS42S32400J datasheet](https://www.issi.com/WW/pdf/42-45S32400J.pdf), page 1, establishes 4M × 32 organization, four banks, row A0–A11 and column A0–A7.
- [Kioxia e-MMC product brief](https://www.kioxia.com/content/dam/kioxia/shared/business/memory/mlc-nand/asset/productbrief/KIOXIA_e-MMC_Product_Brief.pdf) lists `THGBMTG5D1LBAIL` as 4 GB. The CAD's short description says 4Gbit, so that description must not be used as the storage-capacity authority.

The official [ST product resources](https://www.st.com/en/evaluation-tools/stm32h750b-dk.html) also list a [B04 schematic PDF](https://www.st.com/resource/en/schematic_pack/mb1381-h750xb-b04.pdf). Retrieval of this PDF did not succeed in this review; its contents were not used as evidence. The supplied CAD records and the sources above were inspected directly.

Reproduce extraction from the repository root with `PYTHONPATH=build/bdp-review/parser-deps .venv/bin/python build/bdp-review/extract_schdoc.py`. The ignored script preserves raw record order and writes file SHA-256 hashes and record counts to `build/bdp-review/raw/manifest.json`. Nineteen schematic files were extracted; `FDCAN.SchDoc` contains 882 records. No Altium compilation or PCB design-rule verification was performed.

## CAN routing established by the supplied CAD

| Function | CAD design evidence | Firmware comparison |
|---|---|---|
| CAN1 controller signals | `FDCAN.SchDoc` records 60–67, 223–227, 246–260 and 563: PH13/FDCAN1_TX goes to U22 TXD pin 1; PH14/FDCAN1_RX goes to U22 RXD pin 4. MCU-I/O sheet records 435/436 and 4329/4331 identify B17/D16. | `Src/app_can_config.c:5` selects FDCAN1, PH13 TX, PH14 RX and AF9. Mapping agrees. |
| CAN1 physical interface | U22 value `MCP2562FDT-H/SN` (records 243/263/287). CANH pin 7 routes to **CN11 pin 1** and CANL pin 6 to **CN11 pin 2** (258/256, connector 789/791/818, wire 824/825). | The intended board already contains a transceiver. A second external transceiver is not established as necessary by this BDP. The actual board assembly still needs verification. |
| CAN1 supplies/standby | U22 VDD pin 3 connects to 5V (250, 234/236, 66); VIO pin 5 to 3V3 (254,226,67). STBY pin 8 connects through **R225 10K** to GND (260,227,344/346/350,63). | No separate MCU standby GPIO is shown for this transceiver. A software-controlled standby feature cannot be inferred from this board design. Microchip documents low STBY as normal operation. |
| CAN1 termination/protection | **JP7 in series with R224 120R** between CANH and CANL (466/468,492/494/498,673–675,824/825). U30 value `ESDCAN02-2BWY` and its connections appear in 644/666,827/828. | Jumper population and the total external-bus termination are unknown. CN11 is a two-pin CANH/CANL header; a vehicle ground/harness arrangement cannot be inferred from it. |
| CAN2 | PB13 TX/PB5 RX (69/70,74/75,296/302), U21 `MCP2562FDT-H/SN` (293/313/337), **CN10 pin 1 CANH / pin 2 CANL** (831/833/860,866/867), JP6/R222 120R (448/528/530/534) and U29 protection (750/774). | Application configuration implements CAN1 only. CAN2 requires another instance/configuration, message-RAM allocation and protocol routing only if the actual application needs a second bus. |

`Src/app_can.c:712` selects HSE and lines 719–727 configure classic CAN, normal mode, automatic retransmission, prescaler 5, TSEG1 8 and TSEG2 1. With the configured 25 MHz HSE and an undivided kernel clock, this corresponds to 500 kbit/s and a 90% sample point: `25,000,000 / (5 × (1 + 8 + 1))`. This is a calculation from configuration, not a measured bus rate or confirmation of the eventual BMS requirements. The BDP does not specify vehicle message IDs, periods, scaling, diagnostics or safety limits.

## Display and memory comparison

| Area | Established design/source facts | Remaining code or verification work |
|---|---|---|
| LCD U33 | `LCD4.3.SchDoc` record 1063 Value is **RK043FN88H-CT661C**; record 981 LibReference remains RK043FN78H-CT661C. RGB/sync/control routing and PD12/PD13 touch I²C labels are present. The CAD description is 480 × 272. UM2488 Table 19 explicitly identifies a firmware impact for the LCD replacement. | `Src/Lvgl_Porting/lvgl_port_lcd.c:140` uses RK043FN48H timing constants and an HBP-minus-11 adjustment. The old symbol names alone do **not** prove failure. Obtain the actual panel identity and authoritative timing/reset/polarity requirements; verify or implement a named panel profile and a display test pattern. The current LTDC horizontal values imply 491 active clocks (`AccumulatedActiveW - AccumulatedHBP`), whereas the layer width is 480: reconcile this deliberate-looking adjustment with panel documentation before changing it. |
| eMMC U11 | `eMMC.SchDoc` records 1193/1262/1282 select **THGBMTG5D1LBAIL**. Data D0–D7, clock and command routing correspond to SDMMC1. The readme's truncated part spelling and the CAD 4Gbit description are inconsistent with the exact part parameter/manufacturer brief. UM2488 Table 19 describes the memory replacement as having no firmware impact. | Existing `Drivers/BSP/STM32H745I-DISCO/stm32h745i_discovery_mmc.c:195` uses SDMMC1 with an eight-bit bus, matching the route. Do not replace this driver merely because the memory name changed. Read card identity/capacity on the actual board, validate the reserved log region and exercise writes/readback/export. Logging and export defects are addressed separately in the firmware report. |
| SDRAM U7 | `SDRAM.SchDoc` records 1690/1695 select **IS42S32400J-6BL** while record 1507 LibReference remains IS42S32400F-6BL. Harness records 82/85/86 route **D0–D15 and NBL0/1**, not all 32 data bits. DQ16–DQ31 route through resistor pull-down networks (1377–1407); DQM2/3 have separate resistors (1408–1411). UM2488 states that only half the 128-Mbit density is accessible. This is **8 MiB** by design, consistent with 4 banks × 4096 rows × 256 columns × 2 accessible bytes. | `stm32h745i_discovery_sdram.c:133` correctly selects a 16-bit FMC bus with 12 row bits; width 16 is **not a mismatch**. Reconcile the unreferenced `SDRAM_DEVICE_SIZE 0x200000` (2 MiB, header line 64), `Src/main.c:207` MPU 32 MiB region and the actual 8 MiB accessible capacity in one board profile. No bad address access was demonstrated by those differing declarations. Validate timing/refresh for the identified component and use an address-alias/readback test before relying on the full range. |
| QSPI U1/U2 | `QSPI.SchDoc` records 788/823/847 and 1013/1048/1072 specify two **MT25QL512ABB8ESF-0SIT** devices. Sheet notes 94–104 also describe the alternative twin-die MT25TL01G configuration and required resistor/bridge settings. Two 512-Mbit devices provide 128 MiB total capacity; the readme/CAD do not prove what is physically mounted. | `Src/main.c:50` selects QPI/DTR/dual-flash through the MT25TL01G component interface; linker `stm32h750xb_flash.ld:40` reserves 128M mapped QSPI. Names alone do not establish incompatibility with the two-device arrangement. Verify both JEDEC IDs, wiring variant, command support, mapped readback and programming-loader support on the actual board. The UI code/assets placed there must be programmed as well as internal flash. |
| Power profile | H750XB variant bridge settings above align with `Src/main.c:84`, `PWR_LDO_SUPPLY`. UM2488 documents distinct H750XB LDO and H745XI SMPS defaults. | Identify the board variant/revision and any modified bridges before choosing a power profile. BDP presence is not proof of the physical supply configuration. |
